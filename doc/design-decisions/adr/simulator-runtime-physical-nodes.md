# ADR：模拟器运行时物理节点管理

- 日期 2026-11-20
- 状态 已实施

## 背景

模拟器允许通过场景配置声明多个物理节点。运行中增删单个节点时，其他节点的匹配池、
当前轮次、Match 历史和持续流量应继续由当前运行时持有。Client Router 已具备以物理节点
为单位更新路由的能力。

## 方案

| 方案 | 影响 |
| --- | --- |
| 更新场景后发布完整新运行时 | 复用初始化路径，整个集群的等待状态、轮次和事件订阅随运行时切换 |
| 在当前运行时按物理节点提交变更 | 在同一锁内准备并更新目标节点、路由和场景，其他节点继续使用原有匹配池 |

## 决定

运行时提供创建和删除命令。新增先验证候选场景并建立目标节点，再提交路由、身份映射和节点状态。
重复创建同一物理 ID 返回冲突。创建时可提供完整规则部署列表，空列表适用于待部署节点。
删除使用物理 ID，移除目标部署和等待 Ticket，释放对应节点和 Provider；重复删除可以成功重试。
Match 历史、轮次和持续流量保持独立生命周期。

变更与模拟器现有命令使用同一个运行时锁。新增失败时关闭候选节点资源并保留现有运行时。
新增节点在活动轮次中使用当前轮次的时间初始化。路由更新复用 `Router.UpdatePhysicalNode`，同一
场景和 Router 使用同一 `identity.LogicalNodeKey` 和 `identity.PhysicalNodeID`，
路由发布前按共享键校验部署唯一性。其他匹配池无需重建。

HTTP 删除通过查询参数接受规范十进制物理 ID。`GET /api/v1/scenario`
和 `GET /api/v1/topology` 反映提交后的配置。界面和实际错误语义见
[模拟器界面](../../simulator/interface-guide.md#运行时物理节点)和
[HTTP 契约](../../../api/openapi/simulator.yaml)。

## 清空等待队列

清空与删除节点使用各自的操作。清空在模拟器锁内向现有 owner 协程提交一次，复用逻辑节点
的删除路径更新队列和索引。核心完成后同步清除等待观测，并发布一条汇总事件。开始清空后
等待核心确定结果，使请求取消时核心和观测仍保持一致。部署、Provider、调度器、路由与
Match 历史继续由当前运行时持有。
