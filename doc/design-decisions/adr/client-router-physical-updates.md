# ADR：Client Router 物理节点级路由更新

- 状态：已实施
- 日期：2026-11-20
- 范围：`pkg/client.Router` 路由视图更新和候选顺序

## 背景

宿主可能只需变更一个物理节点的 Endpoint、启用状态、权重或规则部署。原有 `Replace`
要求调用方构造完整路由表；单条部署各自更新则可能在中途留下节点配置与部署不一致的
视图。路由表还可以被多个 Router 共享，自定义选择器可能依赖候选顺序。

## 备选方案

1. 只提供完整表替换：校验边界明确，单节点变更也需由宿主重建完整表。
2. 提供单条物理路由和规则部署的独立补丁：调用灵活，但一次业务变更可能暴露多个中间
   状态，还需要额外定义跨补丁的事务及顺序语义。
3. 以物理节点为更新单位：一次提交节点配置和完整部署列表，或通过空列表使节点下线；
   其他节点及部署保持原状，多节点事务继续使用完整表替换。

## 决定

采用方案 3。`UpdatePhysicalNode` 根据非零 PhysicalNodeID 更新单个节点；非空部署列表
新增或完整替换其 `PhysicalRoute` 和全部 `RuleRoute`，空列表则使节点及其全部部署下线，
重复下线成功。更新先校验新视图，再在单一 owner goroutine 的命令边界发布。校验失败
保留当前视图；共享原表的其他 Router 保持原有视图。宿主必须串行调用路由和更新方法，
并负责配置分发及跨进程事务。

同一规则在目标节点上更新前后均存在时保留原候选位置；新加入的部署追加到该规则已有
候选之后。这个约定减少仅修改节点配置时对顺序敏感的自定义选择器的影响，同时允许删除
后重新加入的部署取得新位置。

## 影响和代价

- 宿主每次提交目标节点的完整部署列表；空列表会移除物理节点及其部署。非空列表必须
  满足完整路由表的身份、唯一性和权重约束，节点和部署的启用状态决定新 Ticket 的候选。
- 修改或移除部署可能改变新 Ticket 的选择结果；下线节点的已有 Owner 无法解析。需要
  保留已有 Owner 时，宿主可保留部署并禁用节点或部署，并按生命周期安排旧部署排空。
- 跨节点原子变更或 PhysicalNodeID 变更使用 `Replace`。
- 生成并发布新路由视图需要额外工作和内存，以保留旧视图、失败回滚及 Router 间隔离。

调用方式与完整行为见[路由接入说明](../../match-system/client-router.md#按物理节点更新路由)。
