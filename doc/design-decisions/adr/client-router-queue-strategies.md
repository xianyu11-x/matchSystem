# ADR：物理节点路由快照与队列选路

- 状态：已实施
- 日期：2026-11-23
- 范围：公开 Go API 与独立 Go 消费者示例

## 背景

旧的客户端路由表由宿主提供目标身份、启用开关、Endpoint 和权重。`PhysicalNode`
知道部署的当前状态和等待 Ticket 数。要支持按队列负载选择目标，需要将这些运行状态
交给客户端，并保留客户端创建时选择算法的能力。

## 备选方案

- 由物理节点同时返回运行状态和 Endpoint、权重等配置，可以减少宿主组装步骤，但会让
  匹配核心持有路由配置。
- Router 在每次选路时获取节点状态，可以缩短数据延迟，但为选路请求引入状态读取开销。
- 物理节点提供独立运行快照，宿主补充配置并发布路由。该方式允许进程内调用和跨进程
  传递各自选择合适的实现，选路读取 Router 已发布的视图。

## 决定与影响

- 采用宿主发布方式。`RouteSnapshot` 由物理节点的 owner 协程读取。宿主按部署生命周期
  设置可选状态，并在 Router 的 owner 协程一次提交该物理节点的完整路由。排空期间
  保留部署以解析已有 Owner，停止后在下一次发布时移除。
- `RuleRoute` 和选择器候选携带等待 Ticket 数。加权 Rendezvous 继续作为默认策略。
  新增队列反比权重随机策略，以及以配置权重优先、队列阈值切换、全满时回退最短队列的策略。
- 选路以最近发布的队列数为准。宿主决定同步频率，路由决策和实际入队之间可以存在延迟。
  权重优先策略的阈值在状态发布后影响后续请求，允许满载时继续选路。
