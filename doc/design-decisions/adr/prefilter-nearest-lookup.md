# ADR：Prefilter 最近值查询与 AND 分层

- 状态：已实施
- 日期：2026-11-24
- 范围：`prefilter/v3`、`int64_range` 索引、模拟器规则配置

## 背景

入队时间和段位等 `int64` 属性需要按距离取近邻。固定宽度的范围在数据稀疏时可能选不到
足够的值，在密集时又可能给后续评分过多候选。最近值查询按不同值设上限，并保留同值票据。

## 决策

1. 为 `prefilter/v3` 添加 `lookup_nearest`，复用 `int64_range` 的有序索引值和 posting。
   查询沿左、右或两侧选择指定数量的值，结果仍为候选 Bitmap。
2. `and` 将直属最近值查询放在本层普通条件之后，并保持多个最近值查询的相对声明顺序。
   含直属最近值查询的 `and` 独立求值，完成后与传入候选集合取交集。
3. 使用标准布尔节点表达查询条件。需要对已选出的最近值继续筛选时，将最近值查询放进内层
   `and`，由外层 `and` 处理后置条件。独立最近值查询以索引全集为起点。

近邻选择取决于查询前的候选集合。若让它直接继承优化器产生的外层 scope，外层锚点选择
就可能改变入选的值。按 `and` 分层将这个边界写进现有表达式，也避免给每个集合变换重复
定义输入条件字段。独立求值的代价是外层过滤无法下推穿过该边界。

已有 JSON 规则继续使用现有版本；含新节点的规则需要支持该节点的编译器。用法和候选预算
见[规则参考](../../match-system/reference/prefilter.md#查找最近的-int64-值)。
