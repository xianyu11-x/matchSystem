# 模拟器表单与图表交互

日期：2026-09-06；状态：已实施。

## 背景

模拟器已有版本化规则与生成器能力，但部分参数只能编辑 JSON；参数编辑、规则图和
分析列表相互分散。界面需要支持清晰的配置、观察、导出流程，并保持真实运行语义。

## 决策

- 使用现有 Schema/RuleJSON 作为配置的唯一契约。表达式表单从 Schema 导出操作与
  输入结构，节点检查器复用同一控件。JSON 只用于文件交换和 HTTP 传输。
- 规则列表由场景草稿驱动；切换、新建、复制、删除前写回当前规则，统一校验并保存全部规则。安全空规则禁止加入与成局，新增后可直接通过表单编辑。
- 将常用匹配算法、字段声明、生成方式与低频参数分组；低频参数按需展开。窄窗口
  保留完整页面导航，网格控件顶部对齐，增加可读字号与键盘焦点。
- 批量生成的共同 Object Facts、时间步长、路由/请求前缀直接映射已有模拟器宿主能力。
  客户端批量失败处理默认选择撤回本批已加入对象，用户可以在表单中关闭；使用已有
  `/tickets/batch` 的 atomic 行为。持续流量逐次注入，不套用整批撤回或模拟时间步长。
- 单条输入不静默过滤非法数字。规则数值模型仍为 JavaScript Number，越界报错；
  属性生成的 int64/uint64 区间继续用十进制文本精确传输，避免浮点中转。
- 图表和导出使用同一份“时间窗口 ∩ 所选比赛”数据模型。缺失样本留空、真实零保留；
  图片导出完整分析范围，屏幕缩放只用于浏览。CSV 是聚合图点数据，不冒充原始备份。
- 复用 ECharts 与浏览器/桌面宿主下载。真实 WebView2 已验证三种格式落盘，因此不
  引入额外保存命令或权限；提示只确认下载请求，不将用户取消视为成功。

## 代价与验证

完整表单需要随着契约同步维护字段语义和帮助文字；Schema 派生操作及保存/运行回归
用于防止能力落后。表单仍需 Go 编译与 Provider 握手，元数据声明不能产生动态业务函数。
界面简化不改变 LogicalNode 状态隔离、规则评估或运行预算语义。
