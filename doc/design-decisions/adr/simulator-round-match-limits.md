# ADR：物理节点独立匹配配额与只注入模式

- 状态：已实施
- 日期：2026-11-24
- 范围：模拟器轮次、持续流量、HTTP 与 Web 配置

原有模拟器将本轮所有物理节点的成局数与一个全局上限比较。节点数变化时，需要相应
修改全局配置才能表达每台节点的目标处理量。持续流量还需要一种能构建待匹配队列的
只注入配置。

1. 手动和定时轮次使用每物理节点的成局配额。轮询仍按物理节点 ID 顺序重复执行，某个
   节点用完自己的配额时跳过该节点，其余节点继续。配额统计成功 Match，各节点的
   Match 用同一个轮次编号汇总。逻辑部署继续由物理节点选择器调度。
2. 持续流量显式传入 `maxMatches: 0` 时只运行到达与注入。实时调度不以匹配间隔唤醒，
   固定步长不触发匹配，流量状态的匹配轮数和产出局数都是 0。
3. HTTP 的手动轮次保留缺省或 `0` 的旧语义及 `matchLimit` 兼容字段。持续流量请求的
   `maxMatches` 继续必填，显式 `0` 才表示只注入。

选择保留模拟器原有的串行轮询，以维持成局记录顺序和既有错误处理。配额变化后，一个
请求的总产出可达「物理节点数 × 单节点上限」，调用方继续读取响应中的实际总局数。
参见[手动匹配](../../simulator/interface-guide.md#运行一轮)和[持续流量](../../simulator/continuous-traffic.md)。
