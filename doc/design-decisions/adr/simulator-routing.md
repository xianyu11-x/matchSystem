# ADR：模拟器路由同步与算法配置

- 状态：已实施
- 日期：2026-11-23
- 范围：模拟器运行时、场景契约、HTTP 和 Web

## 背景

模拟器原先根据场景部署配置构造 Router。队列感知算法需要知道候选逻辑部署的等待 Ticket
数。模拟器可以读取各物理节点提供的快照，也需要模拟真实部署里的上报间隔。

## 备选方案

- 每次选路前采集所有候选的当前状态。队列数据更新及时，选路需要跨节点读取，并且无法模拟
  上报延迟。
- 按物理节点定时发布快照。选路读取已发布的路由视图，上报频率可以按节点配置。
- 通过完整场景替换改变算法。沿用场景接口，但重建物理节点并清除原运行态。
- 用当前运行态快照创建新 Router 并交换。保留节点、队列、匹配历史和流量，新增轻量的
  算法配置入口。

## 决定与影响

- 节点加载或部署变更成功后立即发布快照，之后按每个物理节点的实际时间间隔同步，默认
  10 秒。模拟器作为宿主在节点 owner 协程读取，在模拟器运行时锁下发布。固定步长流量
  使用虚拟匹配和到达时钟，路由快照仍按实际时间上报。
- 场景中的 `routing` 决定 Router 构造时的选择器，省略时使用加权 Rendezvous。运行中的
  策略切换通过新 Router 实例提交，使当前部署和已保存 Owner 可继续使用。
- 各节点的快照提交独立进行，队列感知算法会看到上一次同步的 Ticket 数。实时阈值和重放
  结果受同步时机影响。节点下线、场景替换和模拟器关闭取消对应同步任务。

操作与参数见[模拟器路由配置](../../simulator/routing.md)。
