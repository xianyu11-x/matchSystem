# 界面操作与配置

从运行总览按“配置规则 → 注入对象 → 分析结果”完成一次模拟。侧栏和窄窗口顶部均有
四个页面的导航；键盘用户可通过“跳到主要内容”和可见焦点定位操作。

输入面板统一保留 24 px 内边距；字段标签与控件共用网格边界，运行表单保留 20 px
内边距和 16 px 组间距。总览操作步骤与指标卡之间留出独立间隔，趋势为空、加载中或失败
时使用带留白的状态区域。桌面“客户端更新”使用顶层模态对话框，拓扑和页面控件不会覆盖
它；Tab 在对话框内循环，Esc 或“关闭”返回入口，正在安装时禁止关闭。

总览与分析页中的图表共用内容边距，导出操作、说明和展开的数据列表都保留卡片内侧
20 px 留白；已有外层留白的 Ticket 属性面板不会重复缩进。数据表使用 12 px 字号，窄窗
口在表格内部横向滚动。筛选框跟随表单宽度，仅列表工具栏的短筛选项保留紧凑宽度。
未展开的属性生成卡保持自身高度，不随相邻展开卡拉伸；比赛选择区与分析卡保持间隔。

## 匹配对象

对象列表支持 25/100/250 条分页和首页/前后页导航。搜索、状态或页大小改变时返回首页；
实时队列变化可能移动偏移分页边界，列表不承诺跨页快照一致性。表单标签和控件字号统一
提高到 13/14 px，并补充清晰键盘焦点，网格内字段保持顶部对齐。


“新建 / 批量生成”中的投递目标适用于单条输入、批量生成和持续流量。

- **指定规则**是默认模式。每个 RuleID 显示一次，有至少一个可用部署的规则可以选中。Router 按
  部署权重和亲和键为每条 Ticket 选择物理节点。省略亲和键时使用 TicketID。权重比例在一批不同键上
  体现为近似分布。
- **指定节点**按 RuleID 和 PlacementID 直接投递到一条逻辑部署。选项展示物理节点 ID、部署位置 ID
  和规则。如果选中的部署失效，需要再次选择目标。

折叠面板保留当前输入。切换规则时按新 Contract 重置属性与事实，切换同一规则的投递方式时沿用
表单草稿。离开页面后草稿不保留。持续流量的目标生命周期见[持续流量与定时匹配](continuous-traffic.md)。

- 单条输入的属性和 Object Facts 来自当前 Contract。空白字段省略，字符串/uint64
  列表支持英文逗号、中文逗号或换行。非法整数、溢出值会显示字段名和范围，不再静默过滤。
  手动数字输入受 JavaScript 安全整数限制，完整 int64/uint64 边界可使用批量生成器的
  十进制文本参数。更多选项可指定创建时间（Unix 毫秒）和路由亲和键。
- 批量生成先设置数量、随机种子和起始 ID，再启用所需属性。分布、集合和共享值详见
  [属性生成配置](attribute-generation.md)。提交前检查区间范围、重叠集合基数、不重复
  抽样数量、缺失/循环共享引用和末尾 ID，服务端仍执行权威校验。
- “共同对象事实”给每条生成对象附加相同 Object Facts，也用于持续流量；不是 Provider
  声明或 Match Facts 配置。字段仍来自当前规则的 object scope。
- 更多选项可设置批量创建时间、每条时间步长、亲和键/请求标识前缀和失败时整批撤回。
  前缀使用首位非零的十进制数字，拼接 Ticket ID 后的值必须能表示为 `uint64`。
  创建时间留空使用服务器当前时间，步长为 0 或省略时默认
  1 毫秒。持续流量使用到达时间，并逐次注入，不使用批量时间或整批撤回选项。
  若持续流量后来生成的 Ticket ID 与前缀拼接后超过 `uint64` 上限，本次流量会进入失败状态。
- 流量启动后锁定生成配置与节奏，停止按钮始终可用。“接续编号”将服务端下一 ID 填入
  起始编号，便于再次启动。它不会绕过其他来源创建的重复 ID 检查。

新增 HTTP 字段 `createdAtStep`、`affinityPrefix`、`requestIdPrefix`、`objectFacts` 在
批量与 custom generator 请求中直接映射已有宿主生成器；不修改匹配核心或 Provider
语义。完整请求契约见 [OpenAPI](../../api/openapi/simulator.yaml)。

## 运行一轮

默认“当前时间”在点击时读取时钟，避免旧页面时间影响等待时长。需要可复现实验时选
“指定模拟时间”。本轮最多产出是规则允许时的上限，未满足条件的对象继续等待。

## 运行时物理节点

在“运行总览”的拓扑面板添加物理节点，或从节点卡片进入编辑。节点 ID 标识物理节点，
Endpoint、启用状态和逻辑节点调度算法决定节点的路由与运行配置。物理节点可配置零条或多条
逻辑部署，每条部署从规则库选择一条规则，填写 PlacementID、权重和启用状态。节点 ID 和
PlacementID 使用正 `uint64` 的十进制文本，支持到 `18446744073709551615`。

已有部署使用已装载的规则。要使用库中的新内容，可在目标部署选择应用规则库版本再保存。
保存只更新本次编辑的物理节点。移除或重新装载某条部署会清除该部署的等待 Ticket，
其余部署的队列与已完成 Match 历史继续可用。删除物理节点会清除该节点的全部部署和等待 Ticket。
[多物理节点运行时](architecture.md#运行时管理物理节点)

## 场景 JSON 导入与导出

总览的当前场景区域提供场景 JSON 导入和导出。导出文件包含 `scenario` 和 `revision` 外层字段，
导入也支持裸场景。场景交换保留原始 JSON 数值文本。导入完整场景会重建运行态并清空运行队列
与 Match 历史，规则库可继续使用。规则文件导入入口在规则配置页。

## 场景部署与 Python Provider

编辑物理节点时，在目标逻辑部署中配置 Tick Facts 和 Python Provider。`describe()` 在装载时
返回实际能力，Fact 元数据接口中的 `providerDescriptors.*.source` 使用 `python` 或 `go`
标识来源。规则库只编辑 Contract 中的 Fact 声明。完整协议见[Python Provider 接入](python-provider.md)。

## 持续流量固定时钟

在 Tickets 页切换“批量与持续流量”，完成目标规则、生成器属性、随机种子、起始 TicketID
和共同 Object Facts 后，在“持续流量与定时匹配”将“模拟时钟”设为“固定步长运行”。填写
“虚拟步数”（1..10000000）、“步长（毫秒）”（1..86400000）和“虚拟起始时间（Unix ms）”
安全整数，再点“开始固定步长运行”。任务会自动推进并在“已完成”状态显示虚拟进度、虚拟
时间和墙上耗时；Python RPC 与匹配计算只影响墙上耗时。详见[持续流量与定时匹配](continuous-traffic.md)。
